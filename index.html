PANDUAN OPERASIONAL & ARSITEKTUR PERSISTEN

Dokumentasi kontrol sistem GASIMA UPMS by ikiygasima

1. PERSISTENT LOCAL RECOVERY LAYER

Seluruh job yang Anda upload/submit langsung dicatat di browser LocalStorage. Jika browser direfresh, server dibersihkan, atau SSE terputus, data tetap utuh dan dapat dipulihkan.

2. DEDICATED PUBLISH QUEUE TAB

Audio berstatus READY otomatis masuk ke tab PUBLISH QUEUE. Klik [PUBLISH ROBLOX] untuk mengirimnya ke platform Roblox. Setelah terkonfirmasi, audio berpindah ke PUBLISHED HISTORY.

3. ISOLATED DELETE & CLEANUP

Penghapusan history lokal pada tab Published tidak akan menghapus asset di Roblox maupun job aktif di server. Seluruh token API Key juga tersimpan aman di server dan tidak masuk LocalStorage.
